RawSTRaP turns text and plain-text documents into CSV records, then saves them to SQLite and, optionally, MySQL. The current application is a local Python desktop app: Tkinter provides the interface, Pillow renders its screen artwork, and provider adapters handle model validation and CSV generation.

> **Billing notice:** API-key validation makes a non-generative model-list request. It does not confirm that generation is free, that quota is available, or that a model will remain accessible. Generation may incur charges. Check your provider's current billing and model access before approving a request in RawSTRaP.

## Features

- Validate a key with a provider model-list request and select an available text-generation model.
- Enter text directly or upload UTF-8 text files: `.txt`, `.md`, `.rst`, `.csv`, `.tsv`, `.json`, `.xml`, `.html`, `.htm`, `.yaml`, `.yml`, or `.toml`.
- Convert sanitized source into CSV using the selected provider.
- Save CSV output in `temp-csv/` and save its rows to a named SQLite table.
- Optionally write the same rows to a MySQL database; the matching local SQLite mirror and CSV are also created.
- Preview saved results in a read-only table and open the output directory from the results screen.

The CSV columns are generated by the selected model; RawSTRaP does not prescribe a fixed extraction schema.

## Supported providers

The application currently includes adapters for:

| Provider | Key validation | CSV generation |
| --- | --- | --- |
| Google Gemini | Model-list request | Gemini generate-content request |
| OpenAI | Model-list request | Responses API request |
| xAI | Model-list request | Responses API request |
| Anthropic Claude | Model-list request | Messages API request |
| Groq-hosted models | Model-list request | Chat-completions request |

The app selects a likely text-capable model from the list returned for the key. Access and billing terms depend on the provider account and can change. Consult the provider's [official API documentation](https://ai.google.dev/api), [OpenAI API documentation](https://platform.openai.com/docs), [xAI API documentation](https://docs.x.ai/), [Anthropic API documentation](https://docs.anthropic.com/), or [Groq API documentation](https://console.groq.com/docs) for current details.

## Requirements

- Python 3.14
- Tkinter support in the Python installation.
- Internet access for provider key validation and CSV generation.
- MySQL server access only if you choose MySQL storage.

```bash
pip install -r requirements.txt
```

Dependencies are listed in [requirements.txt](requirements.txt). MySQL support uses `mysql-connector-python`.

## Installation

From the project directory, create and activate a virtual environment, then install the listed dependencies.

**Windows (PowerShell):**

```bash
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

**macOS / Linux:**

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

NOTE - If Python reports that Tkinter is unavailable, install the Tk components supported by your operating system or use a Python distribution that includes Tk.

## How to use

Start the desktop application from the project directory:

```sh
python run.py
```

1. Select an API provider and continue.
2. Enter the provider key. RawSTRaP makes a model-list request to validate it; this step does not send source text or run generation.
3. Choose SQLite or MySQL. For MySQL, enter the connection host, port, username, and password when prompted.
4. Choose **Talk it out!** to enter text or **Upload file** to load a supported plain-text document.
5. Select the destination database and table names when prompted.
6. Review the provider and model confirmation. Continue only after checking your provider's billing status. Declining sends no generation request.
7. If the destination already exists, confirm that rows should be appended. Existing rows are not replaced.
8. After processing, use **Preview File** to inspect the saved table, **Open File Location** to open the output folder, or go back to edit the source.

## Documents created

- **SQLite:** RawSTRaP writes a `.db` file in the project directory, with a table whose text columns are based on the CSV headers.
- **MySQL:** RawSTRaP creates the named MySQL database if it does not exist, creates the table if needed, and inserts the records. It also writes a local SQLite mirror in the project directory.
- **CSV:** Each successful provider response is saved as a uniquely named CSV file in `temp-csv/`.
- Existing table rows are appended to; the application does not replace existing rows.

## Data handling

- Before provider generation, source text is normalized and sanitized by the existing parser. Sanitization removes commas, backslashes, non-ASCII characters, and most control characters, and trims outer whitespace. **Review the sanitized text in the app before continuing**, as this can change the input.
- After the confirmation step, the sanitized source and conversion prompt are sent to the selected provider. Provider usage can be billable.
- The application keeps the API key in process memory for its workflow and does not intentionally write it to a file or log. It does not claim secure erasure from memory.
- MySQL credentials are used to make the database connection and are not written into the SQLite mirror.
- Generated CSV and database files remain on the local machine in `temp-csv/` and the project directory. Keep those locations private if the data is sensitive.

## Development checks

Compile the application modules without making provider requests:

```sh
python -m compileall run.py python-scripts
```

The repository does not currently include a maintained automated test suite. Do not use real API keys or send live requests as part of routine development checks.

## Troubleshooting

- **Tkinter import/window errors:** Use a Python installation with Tk support.
- **Key rejected or provider unavailable:** Check the key, network connection, and provider status. The app maps common authentication, rate-limit, and connectivity errors.
- **No selectable model:** The key may return models that the current selection logic does not identify as text-generation models. Check the provider console and model access.
- **Generation fails or requires payment:** Model-list validation does not establish generation access or cost. Review current account billing, quota, and model permissions.
- **MySQL connection or write fails:** Check the server host and port, credentials, connector installation, and account permissions to create/use the selected database and table.
- **CSV/table validation fails:** The provider response must be valid CSV with a header row and consistent fields. Model-generated columns can vary.
